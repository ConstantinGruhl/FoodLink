# Distribution implementation contract

All scoped requests use X-Location-Id. All mutations require authenticated CSRF. Booking, item reservation, checkout and closeout accept UUID Idempotency-Key. No global role bypass. Event DTO retains existing fields and adds organizationId/locationId, mode (`items`, `visit`, `packages`), recordingMode (`opening`, `leftovers-only`), walkInCapacity, waitlistEnabled, admissionsClosed, packageLabel, recurrenceGroupId.

- POST /events: existing event fields plus mode, recordingMode, walkInCapacity, waitlistEnabled, packageLabel, slots:[{startsAt,endsAt,capacity}], recurrence:{weeks:1..12}. Location identity comes from scope; legacy location string is display instructions. Returns first Event plus generatedIds. Weekly recurrence preserves local clock time through DST.
- GET /events/:id/details: {event,slots,allocations,bookings,closeout}. Public response has empty allocations/bookings; staff must have scoped read/checkin capabilities. Slots: {id,startsAt,endsAt,capacity,reservedCount}. Allocations: {itemId,name,unit,openingQty,addedQty}. Closeout: stored report or null.
- POST /events/:id/book: {householdId,slotId?,collectorId?,walkIn?:false,overrideReason?,packageCount?:1,notes?:''}. `visit`/`packages` only; scoped checkin staff may book on behalf of approved households without online accounts. Recipient must be a household member. Waitlist returned only if enabled/full; waitlisted bookings do not hold allowance.
- GET /bookings/mine: Booking[] for user's households in selected organization.
- POST /bookings/:id/cancel: {}. Household collector or scoped checkin staff, before cutoff for self-service.
- POST /bookings/:id/checkin: {collectorId?,categoryTallies?:[{category,qty}],overrideReason?}. Scoped checkin staff; records attendance and consumes visit/category allowance, prevents repeat handout. Manually assisted collection can omit collectorId and records the staff actor.
- POST /bookings/:id/no-show: {} scoped checkin; explicit policy determines whether visit allowance is consumed or released.
- POST /bookings/:id/promote: {} scoped checkin; rechecks capacity/eligibility/allowance for waitlisted household.
- Booking: {id,eventId,organizationId,locationId,householdId,householdLabel,slotId,collectorId,bookedBy,status,walkIn,packageCount,reference,notes,createdAt,checkedInAt,event?}. Status confirmed/waitlisted/checked-in/completed/cancelled/no-show.
- GET /allowances?householdId=&at=: {householdId,periodStart,periodEnd,visitLimit,usedVisits,remainingVisits,categoryLimits,usedCategories,noShowConsumes,allowOverrides}. `at` optional ISO date-time for upcoming event period. Self membership or scoped people/checkin staff required.
- GET/PATCH /allowance-policy: {periodDays,visits,perMemberVisits,categoryLimits:{category:number},noShowConsumes,allowOverrides}. Policy writes charity manager only. Periods align to 1970-01-05 local calendar days; default seven-day period means Monday–Sunday. One household allowance spans charity locations.
- POST /events/:id/allocations: {items:[{itemId,qty}],notes?}. Scoped inventory staff. Deducts uncommitted aid stock; allocated units cannot be sold/reserved elsewhere.
- POST /events/:id/stop-admissions: {} scoped events staff.
- POST /events/:id/closeout/preview and /closeout: {lines:[{itemId,leftoverQty,lossQty,distributedQty?,discrepancyQty?,notes?}],newLeftovers?:[inventory batch fields],notes,estimatedDistributedQty?:number}. Scoped events staff. All existing allocations must appear exactly once. Opening-known requires explicit distribution quantity and accounting equality; discrepancy separately reported. Leftovers-only distribution remains unknown, estimate separately labeled. New leftovers require source/handling metadata and cannot duplicate an existing batch. Closeout requires stopped admissions and resolved active bookings/orders, returns report; repeated same body is safe, changed repeated body is rejected.
- GET /events/:id/report: confirmed report, scoped read.
- GET/PATCH /seller-settings: {enabled,mode:'disabled'|'local-fixture',destinationLabel,currency}. Scoped charity manager writes, scoped manager reads. Fixture only, no provider setup.
- POST /orders/reserve: existing basket plus householdId?,slotId?,collectorId?. Household inferred for self if omitted; one household place/event, category allowance held atomically. Cross-location items/events rejected.
- POST /orders/checkout: existing basket; single charity/location seller, returns {order,checkoutUrl,simulated:true} in enabled local fixture mode.
- POST /orders/:id/simulate-payment: {outcome:'paid'|'failed'}, owner only, local fixture order only. Explicit simulation label; no external requests. Existing order cancellation/refund/fulfillment remain scoped and transactional.

Tables: 008 defines event_slots, event_bookings, allowance_policies, allowance_holds, seller_settings, event_allocations and event_closeouts. Item qty is uncommitted balance; event allocation subtracts qty once, confirmed closeout adds counted leftovers once. Only after this confirmation may approved automatic surplus rules publish leftover stock. No time-based automatic stock release.
